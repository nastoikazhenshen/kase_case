## Работающий сценарий и покрытие

В интерфейсе есть явная кнопка «Показать расчётный пример»: она выбирает реальный инструмент/дату и отдельно подписанную условную сумму пользователя. Исходное состояние оставляет сумму пустой; ноль остаётся числом. Формула, единицы, округление исходного оборота и гипотетический порог показаны рядом. UI, JSON, CSV, HTML, XLSX и слайд 6 используют один отчёт `BS3-REPORT-a9c167a239e236660e1a`.

Покрытие: пять KZT купонных выпусков, десять сохранённых строк за 20–21.10.2026. Режим подтверждён только для четырёх строк 21 октября: BIGDb5 — TQOB; CLSGb11, CLSGb15, MFKMb10 — EQOB. Для HCBNb19 и предыдущей даты режим не доказан. Девять официальных оценок трёх выпусков за 19–21 октября хранятся отдельно от торговых наблюдений. Есть одно полное сообщение CLSGb11; это не полная лента событий.

Из шести реализованных правил одно — отношение пользовательской суммы к опубликованному дневному обороту — доступно на четырёх строках при вводе суммы. Пять ценовых/исторических правил остаются заблокированы. Средний размер сделки является описательной статистикой, а не вторым формальным сигналом. Заблокированное правило не означает отсутствия риска или возможности исполнения заявки.

В дополнительном ограниченном сборе выполнены ровно три разных подхода: официальная PDF-спецификация IRIS, публичная SSR-страница корпоративных облигаций, публичная страница результатов торгов. Все три ответа HTTP 200 сохранены с UTC-временем и SHA-256, но не дали ни одного нового допустимого наблюдения или привязки ценовой базы к архивной строке. Дальнейших повторов/обхода WAF не было. Подробности: `mvp/implementation/finalization/acquisition/`.

Ценовая база не доказана, финальность остаётся `AS_PUBLISHED_NOT_CERTIFIED_EOD`, допустимой предшествующей истории нет. У сообщения не напечатан часовой пояс публикации: применяется консервативная доступность с 22.10.2026 00:00 +05, дата события 19 октября хранится отдельно. ## Запуск и оставшиеся действия

Из корня репозитория в текущем подготовленном окружении:

```powershell
mvp/.venv/Scripts/python.exe -m streamlit run mvp/src/app.py --server.address 127.0.0.1 --server.headless true --browser.gatherUsageStats false
```

Для нового клона сначала создать Python 3.12 venv, установить `mvp/requirements.lock.txt` и выполнить безопасное восстановление `python mvp/scripts/restore_evidence.py "путь/к/bondscope-evidence-final-20261022.zip"`. Полная последовательность — `mvp/README_run.md`. Авторский Node runtime нужен только для пересборки XLSX/PPTX, не для работы приложения.

Команде: вставить готовые два слайда в согласованный общий deck; проверить финансовую копию в нативном Excel/LibreOffice; участникам 1/3 согласовать SAM, налоговое покрытие и проверку тарифа/платных пилотов. Предложения по чужим файлам лежат в `mvp/implementation/finalization/finance_teammate_suggestions.md`.

После демо: урегулировать права на передачу данных, получить официальный датированный экспорт с привязкой ценовой базы/режима/финальности, накопить минимум десять сопоставимых финальных предшествующих дней, уточнить временную семантику и полноту событий. Только новые проверенные доказательства могут открыть заблокированные правила. Эти внешние ограничения приняты для текущего демо, а не объявлены решёнными.

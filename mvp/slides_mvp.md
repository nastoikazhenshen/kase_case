# MVP: вставка слайдов 6–7

## Слайд 6. Проверка дневного оборота BIGDb5

Дата и выпуск определяются локальным отчётом. Пользовательский гипотетический
ввод в KZT делится на наблюдаемый округлённый дневной оборот в KZT. Порог —
гипотеза правила, поэтому расчёт не подтверждает исполнение сделки и не
является инвестиционной рекомендацией. Точные source-derived значения
содержатся только в локальной вставке слайда и связанном отчёте.

В текущем срезе реализованы шесть правил. Одно формально вычислимо на четырёх
строках; пять правил блокируются неполными условиями по ценовому виду, режиму
торгов или сопоставимой истории. Локальная вставка содержит фактический
проверенный снимок UI из офлайн-браузерной проверки.

Источник: KASE, карточка BIGDb5 https://kase.kz/ru/investors/bonds/BIGDb5.
Локальный снимок `BS3-40698bfc0c453479`; отчёт
`BS3-REPORT-a9c167a239e236660e1a`.

## Слайд 7. Концепция продукта и шесть месяцев до готовности

Концепция A/B/C показывает будущий продукт: A — монитор исключений, B —
контекст ликвидности до сделки, C — события эмитента. Отдельная цепочка работы:
watchlist, очередь исключений, аудит-отчёт. Интеграция KASE, IRIS и API в MVP
не реализована. Демо использует локально сохранённые публичные наблюдения;
целевой контур требует лицензированных данных и согласованных прав.

| Этап | Критерий выхода |
| --- | --- |
| M1 — спецификация и права | Доступ к данным согласован |
| M2 — ETL и качество | Поля и происхождение проверены |
| M3 — объяснимые правила | Пороги и проверки согласованы |
| M4 — UI и интеграция | Очередь и контракт интеграции готовы |
| M5 — пилот и тесты | Принятие и воспроизводимость подтверждены |
| M6 — готовность к промышленной работе | Владелец принимает решение о запуске |
